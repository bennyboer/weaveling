# access

Who may do what, as far as a feature has heard. Each feature that asks whether someone may read or change a project, or runs the instance, keeps its own answer in its own database, from what the members, projects and accounts features tell, rather than asking one feature for all at every request; so it depends on none of them at work, and hears a change some milliseconds after it is made.

**`AccessCatalog` is the port,** written in the caller's [transaction](../transacting/README.md) as a feature's listener takes a word in, and read on its own:

- `remember_role(project, account, version, role, at)`: an account's `Role` in a project, `Owner`, `Author` or `Reader`, or with none that it is a member no more; `Role::permits(act)` says which acts each allows.
- `remember_disbanded(project, version, at)`: the project's members disbanded, its project deleted, so nobody is a member of it whatever is heard of it after.
- `remember_trash(project, version, in_the_trash)`: whether the project is in the trash.
- `remember_operator(account, version, operator, at)`: whether the account runs the instance.
- `role_of`, `is_in_the_trash`, `projects_of` (neither disbanded nor in the trash), `share_a_project` and `operates` answer them.

**Every word comes with the version of what it is about,** the project's members, the project or the account, and the newest heard wins, as a message refused may be tried again after newer ones: a word heard late or twice changes nothing. What has ended, a membership, an operator's running of the instance, a project disbanded, stays as a tombstone with when it ended, so an older word heard after it does not bring it back; `forget_tombstones_laid_before(before, at_most)` lets them go, for each feature's tombstone chore, once nothing can be heard late any more.

**`KeptAccess` is the `Authorizer` over it,** as the members feature's own answers: the system may do everything and nobody signed in nothing; an account may do what its role permits, and in a project in the trash only restore it; it reads the projects it is a member of, and runs the instance as last told (`Authorizer::operates`, which `AllowingEverything` answers yes to, so without accounts the one working runs it). A feature's listener tells it through `remember_role`, `remember_disbanded`, `remember_trash` and `remember_operator`, in the listener's transaction, and once that is committed whoever follows the project live is told its access changed, so a socket closes for one who may no more. `share_a_project` answers whether two accounts meet in a project, as the assets ask before showing an account's own.

**The library knows no feature's contract,** so libraries stay below features without exception: the contracts that publish the events lay the listeners out instead, each a macro, `members_contract::access_roles_listener!`, `projects_contract::access_trash_listener!` and `accounts_contract::access_operators_listener!`, written in the feature's messaging crate as one line each, naming the listener, the core, its name and what is wrong when it is refused. What they hear they tell the core through `HearsAccess` (`remember_role`, `remember_disbanded`, `remember_trash`) and `HearsOperators` (`remember_operator`), traits each core implements, so the compiler holds every feature to hearing alike; a macro adds nothing to a contract's own dependencies, which stay fit for the browser.

**Each feature lays the tables down in its own database,** as with [`belonging`](../belonging/README.md), a shared mechanism rather than shared data: `access_roles`, `access_disbanded`, `access_trash` and `access_operators`, with their own migration ledger, `_sqlx_migrations_access`; in memory, on PostgreSQL and on SQLite, held to one conformance suite. What is told is written in the caller's transaction; what is asked is read on the feature's own pool, so the `Authorizer` over it answers without one.
